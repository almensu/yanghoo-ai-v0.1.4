# 阶段 9B：任务列表现代化视觉刷新

## 背景

阶段 8A 已让任务列表具备搜索、筛选和资产状态展示能力。下一步需要基于阶段 9A 的设计系统，将任务列表从“功能堆叠”升级为现代、专业、高信息密度的工作台入口。

本阶段只刷新任务列表相关 UI，不重做 Studio。

## 目标

优化以下文件：

- `frontend/src/pages/TaskListPage.js`
- `frontend/src/components/TaskList.js`
- `frontend/src/components/CardView.js`
- `frontend/src/components/TableView.js`
- 必要时补充共享样式或小型 UI helper。

## 设计原则

- 任务列表应像专业 SaaS 工作台，而不是营销页。
- 搜索、筛选、排序是工具条，不是装饰卡片。
- 资产状态 badge 要清晰、紧凑、语义一致。
- 桌面优先高信息密度，窄屏优先可读性。
- 减少大阴影，使用细边框、浅底色、hover 状态表达层级。

## 执行范围

### Step 1 - 顶部工具条

重构任务列表顶部区域：

- 搜索框。
- 平台筛选。
- 归档筛选。
- 资产筛选。
- 排序控件。
- 视图切换。

要求紧凑、对齐一致、移动端可换行但不重叠。

### Step 2 - 任务卡片刷新

优化 CardView：

- 标题、平台、时间、UUID 短码层级清楚。
- 资产状态 badge 使用统一颜色和图标。
- 主操作“进入 Studio”明确。
- 次要操作不要抢主操作视觉权重。
- 卡片边框和 hover 状态统一。

### Step 3 - 表格刷新

优化 TableView：

- 列宽稳定。
- 标题和 URL 长文本不撑破布局。
- 资产列紧凑展示。
- 时间列可扫描。
- 行 hover、选中和操作按钮统一。

窄屏下如果表格不可读，应使用横向滚动或引导切换 CardView。

### Step 4 - 状态页面

统一任务列表中的：

- 首次加载态。
- 空任务状态。
- 搜索无结果状态。
- API 错误状态。

状态 UI 应提供明确下一步操作，例如导入任务或清空筛选。

## 验收标准

- 任务列表整体视觉与阶段 9A token 一致。
- 卡片和表格中的同一资产状态使用同一种表现。
- 筛选工具条在桌面和窄屏下不重叠。
- 无大面积默认 daisyUI/cupcake 观感。
- 信息密度提升，但主要内容更容易扫描。

## 验证命令

至少运行：

```bash
cd frontend && npm run build
```

建议手动检查：

- 无任务状态。
- 有大量任务状态。
- 搜索无结果。
- CardView / TableView 切换。
- 窄屏宽度。
