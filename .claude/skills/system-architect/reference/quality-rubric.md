# 架构文档质量标准

## 必须通过的硬门槛
- 目标清晰，可量化，有口径
- 范围与非目标明确
- 至少两种方案对比，取舍写清
- 关键链路有图，有文字解释
- 非功能需求可落地，SLO 可执行
- 有安全边界与审计点
- 有可观测性与告警策略
- 有灰度与回滚方案
- 有风险清单与对策
- 有开放问题与假设清单

## 快速自检
- 研发能据此拆任务并开工吗
- 测试能据此写用例与压测吗
- 运维能据此写 runbook 吗
- 出故障时能按文档定位与恢复吗

## 常见缺陷
- 只有组件图，没有关键链路细节
- 指标写了但不可测
- 忽略失败模式与降级
- 不写非目标导致范围失控
- 忽略权限与审计导致返工
