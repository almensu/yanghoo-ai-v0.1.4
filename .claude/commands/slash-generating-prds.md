# PRD Generator

Invoke the generating-prds skill to generate product requirements documents (PRDs) from messy notes, chats, transcripts, or ideas, producing a clear PRD with goals, scope, requirements, metrics, rollout, and risks.

## Usage

Use this command when you need to:
- Convert messy ideas and notes into structured PRDs
- Create comprehensive product requirement documents
- Define product goals, scope, and success metrics
- Plan rollout strategies and identify risks
- Translate user stories and feature requests into PRDs
- Generate product specifications from brainstorming sessions

## Examples

- `/slash-generating-prds` - Launch with interactive PRD creation
- `/slash-generating-prds "User Analytics Dashboard" "Real-time analytics platform"` - Create PRD for analytics dashboard
- `/slash-generating-prds "Mobile Payment System" "Contactless payment solution"` - Generate mobile payment PRD
- `/slash-generating-prds "Content Management System" "Enterprise CMS platform"` - Create CMS PRD

## PRD Generation Process

The generating-prds skill will help you create comprehensive PRDs including:

### 1. **Product Overview & Goals**
- Product vision and mission statement
- Key business objectives and success criteria
- Target market and user segments
- Competitive landscape analysis
- Strategic alignment with company goals

### 2. **Scope & Requirements**
- **Product Scope**: Clear in-scope and out-ofcope features
- **Functional Requirements**: Detailed feature specifications
- **Technical Requirements**: Architecture and integration needs
- **User Requirements**: User stories and use cases
- **Performance Requirements**: Speed, scalability, reliability metrics

### 3. **Success Metrics & KPIs**
- **Business Metrics**: Revenue, user acquisition, retention rates
- **Product Metrics**: Usage statistics, feature adoption, engagement
- **Technical Metrics**: Performance benchmarks, uptime targets
- **User Experience Metrics**: Satisfaction scores, task completion rates
- **Success Criteria**: Clear definition of product success

### 4. **Development & Rollout Plan**
- **Development Roadmap**: Phase-wise implementation plan
- **MVP Definition**: Minimum viable product scope
- **Timeline & Milestones**: Key delivery dates and checkpoints
- **Resource Requirements**: Team composition and budget needs
- **Dependencies**: Cross-functional requirements and external dependencies

### 5. **Risk Analysis & Mitigation**
- **Technical Risks**: Architecture, scalability, integration challenges
- **Market Risks**: Competition, adoption barriers, market changes
- **Operational Risks**: Resource constraints, timeline delays
- **User Risks**: User acceptance, training needs, support requirements
- **Mitigation Strategies**: Contingency plans and risk response

### 6. **Stakeholder Alignment**
- **Key Stakeholders**: Identification and role definition
- **Decision Makers**: Approval process and governance
- **Communication Plan**: Updates and reporting structure
- **Feedback Loops**: User feedback and iteration process

## Input Sources

The skill can process various input formats:
- **Meeting Notes**: Raw transcripts and discussion points
