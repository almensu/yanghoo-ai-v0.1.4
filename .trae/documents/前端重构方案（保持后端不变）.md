## 目标与原则
- 保持后端逻辑与接口不变：不改动现有 REST/WebSocket 契约与路径（如 `TaskListPage.js` 的任务操作与 `wsBaseUrl/ws`）。
- 只重构前端：聚焦可读性、可维护性、性能与一致性。
- 渐进式迁移：按模块分期，确保任意时间点应用可运行。

## 现状概览（依据仓库研究）
- 技术栈：React + CRA（`react-scripts`），JS；Tailwind + DaisyUI；`react-router-dom@7`。
- 入口：`frontend/public/index.html`；`frontend/src/index.js`；主路由容器 `frontend/src/App.js:27–74`。
- 路由：`<BrowserRouter>` + `<Routes>`；侧边栏导航 `frontend/src/components/Sidebar.js:63–77`。
- API：组件内混用 `axios` 与 `fetch`（如 `TaskListPage.js:153–238`、`AIChat.js:168–214/821`）；WebSocket 在 `TaskListPage.js:100–148`。
- 主要问题：
  - 超大多职责组件：`frontend/src/components/AIChat.js`（含模型选择、文档上下文、流式渲染、直接 DOM 操作等）。
  - API 调用分散、错误处理与加载态不统一，混用 `alert`。
  - 直接 DOM 操作与 React 混用（如 `AIChat.js:485–599/629–670/1027–1067`）。

## 目标架构与目录
- 目录分层（仅前端，文件命名示例）：
  - `src/layouts/`：`AppLayout`（承载 Sidebar/Outlet）。
  - `src/features/chat/`：`ChatPage`、`components/`（`MessageList`、`ChatInput`、`ModelSelector`、`ContextPicker`、`ThinkingBlock`）、`hooks/`（`useChatStream`、`useContextSources`）。
  - `src/features/tasks/`：`TaskListPage`、`hooks/`（`useTaskUpdates`）、`components/`（`TaskItem`、`TaskActions`）。
  - `src/services/`：`http.js`（统一 axios 实例）、`api.js`（封装接口）、`ws.js`（WebSocket 管理）。
  - `src/components/common/`：`LoadingIndicator`、`ErrorBoundary`、`Toast`、`ConfirmDialog`。
  - `src/hooks/`：跨模块通用 Hooks；`src/utils/`：工具函数。
  - `src/styles/`：全局样式与设计令牌（延用 Tailwind/DaisyUI）。

## 分期实施
### 第 1 期：统一 API 客户端与错误处理（不改接口路径）
- 新增 `src/services/http.js`：创建 axios 实例，设置 `baseURL`（沿用 `App.js:22–24` 的 `API_BASE_URL`）、超时、拦截器（请求携带必要头、响应统一错误包装）。
- 新增 `src/services/api.js`：按功能分组封装现有接口（任务删除、归档、恢复、下载媒体、提取音频等），复用原始路径与方法；统一返回结构并提供加载/错误态。
- 将 `fetch` 调用迁移为 axios，保持入参与路径一致，例如：`TaskListPage.js:153–238` 等。
- 统一通知机制：用 `Toast` 替代 `alert`；错误收敛到统一处理器。

### 第 2 期：路由与布局抽象
- 抽出 `AppLayout`：包含 `Sidebar` 与主内容 `Outlet`，替换 `App.js:27–74` 的直接页面挂载。
- 路由表集中管理：将 `Routes/Route` 抽到独立配置文件，保留现有路径（如 `/studio/:taskUuid` 在 `App.js:45–50`）。
- 预留受保护路由骨架（当前无鉴权，先提供占位实现，未来接入 Token 即可）。

### 第 3 期：AIChat 组件拆分（行为不变）
- 拆分子组件：
  - `ContextPicker`：管理文档上下文选择与读取（参考 `AIChat.js:167–230/333–359`）。
  - `ModelSelector`：模型与参数选择区。
  - `MessageList`：消息渲染与滚动管理（替代直接 DOM 操作）。
  - `ThinkingBlock`：将 `createThinkingBlock/processThinking` 改为受控 React 渲染（参考 `AIChat.js:485–599/629–670/1027–1067`）。
  - `ChatInput`：输入框与发送动作。
- 新增 `useChatStream`：封装聊天请求与流式处理（沿用 `AIChat.js:812–839` 的 payload 拼装与处理逻辑），仅替代前端实现，接口不变。
- 保持现有 UI 风格与 DaisyUI/Tailwind 原子类。

### 第 4 期：WebSocket 管理与任务页整合
- 新增 `src/services/ws.js`：连接、重连策略、心跳、消息派发；提取 `TaskListPage.js:100–148` 的逻辑到 `useTaskUpdates`。
- `TaskListPage` 精简：状态管理集中、错误与加载态统一、动作按钮通用化（如删除/归档/恢复）。

### 第 5 期：状态管理与通用组件
- 采用 React Context + Reducer 管理跨组件轻量全局态（避免引入新库）：如当前任务、全局通知、主题。
- 通用组件：`LoadingIndicator`、`ErrorBoundary`、`Toast`、`ConfirmDialog`，替换分散的 `alert` 与临时加载占位。

### 第 6 期：样式与主题一致性
- 整理 `index.css` 与组件级 CSS，保留特殊交互（拖拽、滚动）但统一命名与职责。
- 固化 DaisyUI 主题与设计令牌，避免魔法数与重复样式。

### 第 7 期：性能与可维护性
- 页面与重组件按路由懒加载（`React.lazy` + `Suspense`）。
- 列表/消息渲染按需虚拟化（结合已有 `hooks/useVirtualization.js`）。
- 合理使用 `memo/useMemo/useCallback`，避免不必要重渲染。

### 第 8 期：测试与保障
- 为 `services/api.js/ws.js` 编写单元测试（Jest/RTL，CRA 自带）。
- 为 `features/chat` 的关键交互（发送、流式渲染、上下文选择）编写组件测试。
- 路由与页面渲染的基本快照与行为测试。

## 验收标准
- 路由与页面功能保持一致：`/`、`/studio/:taskUuid` 及测试页均可正常访问。
- 任务操作与 WebSocket 更新无回归（参考 `TaskListPage.js:77–93/100–148/153–238`）。
- AIChat 行为一致：请求参数与响应处理等价（参考 `AIChat.js:812–839`），但渲染更稳定、无直接 DOM 操作。
- 错误与加载体验统一，无 `alert`；通知与确认对话统一。
- 代码规模与复杂度下降：`AIChat.js` 拆分后单文件行数显著减少；API 调用集中管理。

## 风险控制与迁移策略
- 按页面/功能逐步迁移，每次只替换一个模块，回滚简单。
- 在 `api.js` 层保留与后端的契约映射，前端内部可渐进调整。
- 通过测试与手动回归保障关键路径（任务、聊天、路由）。
