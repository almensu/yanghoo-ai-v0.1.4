## 目标与边界
- 不改后端契约与接口。
- 建立发布前的端到端质量门：基本 E2E 验收、统一错误展示、覆盖率出报告、CI 持续集成，保证构建可发布。

## 项目现状（依据检索）
- CI：仓库中无 `.github/workflows/*`、`gitlab-ci.yml`、CircleCI 等配置。
- 测试/覆盖率：`react-scripts test` 默认脚本，未启用 `--coverage`；存在 `setupTests.js` 与 `App.test.js`；无自定义 `jest.config.*`。
- 构建与启动：`frontend/package.json`（build/start），根目录有 `start.sh`/`stop.sh` 便于本地并行前后端。
- 错误展示：`services/http.js` 统一错误包装，`Toast.js` 提供通知但未全局挂载为统一入口。

## 工作项
1. 端到端验收（轻量 E2E/集成）
- 使用 `@testing-library/react` 编写关键场景的集成测试：
  - 任务页：加载任务列表、处理 `task_update` 消息的状态更新（可用 mock WS 层）。
  - Chat：发送→增量→最终合并→思考块展示；错误态弹出 `Toast`。
- 不引入新框架（如 Playwright），保持最小增量。

2. 覆盖率出报告
- 通过 `react-scripts test --coverage` 生成覆盖率；将关键测试纳入覆盖统计。
- 若需要，可在 CI 中收集并输出覆盖率摘要。

3. 统一错误展示
- 在 `AppLayout` 或根组件挂载 `ToastContainer`，确保所有页面的错误提示统一显示。
- 保持 `services/http.js` 错误包装；页面侧统一用 `useToast`。

4. CI 持续集成
- GitHub Actions（如仓库将托管在 GitHub）：
  - Node 18/20 matrix，步骤：checkout → setup-node → install → lint → test（含覆盖率） → build。
  - 缓存 npm，提高构建速度。
- 若不使用 GitHub，可改为本地/企业 CI 等价配置。

5. 构建与告警检查
- 保证 `npm run build` 通过；消除高风险 CSS 压缩警告（针对 `index.css`、`App.css`、组件样式）。

## 验收标准
- 关键用户流程集成测试通过；覆盖率报告可生成并≥70%。
- 全局错误提示一致，Toast 正常工作。
- CI 首次运行成功：lint、test、build 全绿。
- 本地构建通过，无高风险构建告警。

## 变更范围控制
- 新增：仅必要的测试文件与 CI 工作流文件；在根或 `frontend` 侧做最小脚本调整以支持覆盖率输出。
- 编辑：在布局或入口处挂载 `ToastContainer`；不改变后端契约与接口。

## 时间与交付
- 1 次迭代完成：补集成测试→启用覆盖率→挂载 Toast→新增 CI 工作流→构建验收；随后进入维护期。
