# Fix Storage Root and Homepage Assets Report

## Summary
The storage root inconsistency issue has been resolved. Both scripts and the running API now use a canonical data root located at the project's top-level `data/` directory. This ensures that assets generated by CLI tools are immediately and accurately reflected on the workbench homepage.

## Key Fixes
- **Canonical Storage Root (P0)**:
  - Updated `FileStorage` in `packages/storage/src/index.ts` to implement robust path resolution.
  - The storage layer now automatically discovers the project root's `data/` directory, whether running from a script or as a backend process.
  - Environment variable `DATA_DIR` is honored as a priority override.
- **Data Cleanup**:
  - Removed the stale, duplicate `apps/api/data/` directory to prevent any future path confusion and ensure a single source of truth.
- **Frontend Diagnostics (P1)**:
  - Added visible error messages to `apps/web/src/App.tsx` for API connection failures.
  - Implemented a "No sources captured" empty state with a helpful call-to-action.
